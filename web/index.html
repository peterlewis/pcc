CONNECTING A REAL CLOCK TWO WAYS · PICK ONE
Standby and Simulation need no hardware. To display a real clock, the app reads its USB serial stream one of two ways. Pick one.
1 · WEB SERIAL — nothing to install
The browser opens the USB port directly. Click CONNECT DEVICE. Needs a Chromium browser (Chrome / Edge / Brave / Arc) on https or localhost; shows a port picker, one tab at a time.
2 · PCC BRIDGE — any browser (+ optional stratum-1 clock)
Opens the port and serves this app to any browser. Download, run, open the address it prints:
# macOS (universal) curl -L https://github.com/peterlewis/pcc/releases/latest/download/pccd-macos-universal.tar.gz | tar xz && cd pcc && ./pccd # Linux (static · x86_64 / aarch64) curl -L https://github.com/peterlewis/pcc/releases/latest/download/pccd-linux-$(uname -m).tar.gz | tar xz && cd pcc && ./pccd
Then open http://localhost:4192 and click CONNECT DEVICE. Checksums + source: releases · build from host/pccd.
Loading this app from peterlewis.github.io instead? Safari / Firefox can't reach ws://127.0.0.1 from https. Open the localhost copy (above).
OPTIONAL — FEED CHRONY (STRATUM-1 NTP)
# add to chrony.conf — Linux: /etc/chrony/chrony.conf · macOS: /etc/chrony.d/*.conf (or brew's /opt/homebrew/etc/chrony.conf) refclock SOCK /var/run/chrony.pcc.sock refid PCC precision 1e-4
Start chronyd first (it creates the socket), then run pccd with -s /var/run/chrony.pcc.sock. On Linux use precision 1e-2: PPS is timestamped on arrival (~ms). macOS uses the USB frame clock (~0.1 ms). Verify with chronyc sources -v.
